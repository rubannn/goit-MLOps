# Звіт: порівняння Fat vs Slim образів

## Порівняльна таблиця

| Метрика | Fat image (`ml-infer-fat:1.0`) | Slim image (`ml-infer-slim:1.0`) |
|---|---|---|
| Розмір image | 6.1 GB | 5.1 GB |
| Кількість шарів | 21 | 15 |
| Найважчий шар | `pip install` торч-залежностей — 4.97 GB; системний debian-шар build-essential та ін. — 656 MB | `COPY /install /usr/local` (готові pip-залежності з builder-стадії) — 4.96 GB |
| Inference результат | top-3 збігається | top-3 збігається |
| Зайві інструменти | `build-essential`, `libjpeg-dev`, `zlib1g-dev` залишаються у фінальному образі; повна debian-база `python:3.13` | Інструменти збірки залишились лише у builder-стадії, у фінальний образ не потрапили; база `python:3.13-slim` |

## Висновок

У fat-образі зайвими виявились системні пакети для збірки (`build-essential`, `libjpeg-dev`, `zlib1g-dev`), які потрібні лише під час встановлення Python-залежностей, але залишаються в фінальному шарі, та важча базова система `python:3.13` замість `slim`.

У slim-образі завдяки multi-stage збірці ці інструменти збірки не потрапляють у фінальний образ - у runtime-стадію копіюються лише встановлені Python-пакети (`/usr/local`) та код і модель. Це зменшило кількість шарів з 21 до 15 і розмір образу приблизно на 1 GB.

Inference-результат не змінився: fat і slim повертають однаковий top-3 для того самого зображення, оскільки обидва використовують ту саму TorchScript-модель (`model/model.pt`) і той самий preprocessing.

Основний внесок у розмір обох образів дають самі ML-бібліотеки (torch/torchvision, ~5 GB), тому виграш slim-варіанту відносно невеликий у відсотках. Пропозиції для подальшої оптимізації:

- використовувати CPU-only збірку torch (`--index-url https://download.pytorch.org/whl/cpu`), яка значно легша за повну GPU-версію;
- розглянути ONNX Runtime замість повного torch runtime для inference-only сценарію;
- прибрати з fat-образу зайві системні пакети, якщо вони фактично не потрібні для роботи pillow/torch на цільовій платформі.
